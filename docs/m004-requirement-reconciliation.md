## Reader and Action

This matrix is for a future M004 validator or executor landing cold on the validation-remediation slice. After reading it, they should be able to decide whether each flagged gap is already proven, deliberately deferred by the existing M004/S08 scope decision, or still needs targeted implementation or requirement updates.

## Scope Boundary

This document reconciles evidence; it does not expand M004 by claiming behavior that lacks implementation and test proof. Deterministic browser proof remains route assembly and fixture proof. Optional live checks remain opt-in, test-library-only when they mutate watched or resume state, and must preserve the existing redaction boundary.

## Reader-Test Notes

A cold reader should first inspect the row for the gap they are validating, then follow the cited test and doc evidence. If a row says deferred or partially proven, validators should not upgrade it to complete without a passing named test or a DB-backed requirement/decision update.

## Redaction Boundary

This document intentionally uses category-level evidence and tracked file paths only. It does not include live Kodi endpoints, media paths, credentials, auth-header values, browser storage keys, raw request or response bodies, prepared stream addresses, or sentinel secret strings.
